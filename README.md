# Expense Tracker

Личный учёт доходов и расходов в одной валюте.

## ЛР-1

Создано стартовое приложение на React, TypeScript и Vite.
На первом этапе отображается главная страница Expense Tracker.

## Требования

- Node.js
- npm

## Запуск

```bash
cd frontend
npm ci
npm run dev
```

## Проверка production-сборки

```bash
cd frontend
npm run build
npm run preview
```

## ЛР-2

Добавлены страницы и навигация на React Router: список операций, карточка по id, страница создания и страница «не найдено», объединённые общим layout.

## Страницы
- `/` -> редирект на `transactions`
- `/transactions` - список операций
- `/transactions/new` - создание (заглушка)
- `/transactions/:id` - подробности операции
- `*` - страница "не найдено"

Записи сейчас демонстрацинные (массив в `src/data/transactions.tsx`)

## ЛР-3

Добавлены формы и локальное состояние: создание, редактирование, удаление и фильтрация операций. Данные хранятся только в памяти и сбрасываются при обновлении страницы.

## Страницы
- / -> редирект на transactions
- /transactions - список операций (с фильтром по типу)
- /transactions/new - создание операции (форма)
- /transactions/:id - подробности операции
- /transactions/:id/edit - редактирование операции
- * - страница "не найдено"

## Возможности 
- Создание операции через форму (название, описание, тип, сумма, дата, категория).
- Редактирование существующей операции той же формой, id сохраняется.
- Удаление операции с подтверждением (window.confirm).
- Отмена редактирования не меняет исходную запись.
- Валидация: название 3–100 символов, сумма > 0, обязательная дата.
- Локальный фильтр по типу операции (все / доходы / расходы) со сбросом.
- Общий источник данных: список и карточка читают один массив из состояния App.

## Ограничения

Данные хранятся только в памяти открытого приложения.
После обновления страницы возвращаются демонстрационные записи из ЛР-2.
Постоянное хранение появится вместе с Supabase.

## ЛР-4

Добавлена загрузка справочника категорий по HTTP. Категория операции теперь
выбирается из списка, загруженного с сервера, а не вводится вручную.
Справочник хранится в `frontend/public/demo/categories.json` и запрашивается
через `fetch`. В форме есть состояния загрузки, ошибки и пустого результата,
есть кнопка повторной попытки без потери черновика.

## Новые возможности ЛР-4
- Загрузка справочника категорий с сервера (`GET /demo/categories.json`).
- Проверка HTTP-статуса (`response.ok`) и структуры JSON (`value is Category`).
- Проверка уникальности идентификаторов в справочнике.
- Состояния загрузки справочника: loading, error, empty, success.
- Кнопка «Повторить» не сбрасывает введённые поля формы.
- Пока справочник не загружен или категория не выбрана — сохранение заблокировано.
- Отмена загрузки при уходе со страницы (AbortController).
- Основной список операций по-прежнему в памяти и сбрасывается при обновлении.

## ЛР-5

Справочник категорий перенесён в Supabase (PostgreSQL). Форма загружает
категории из реальной базы данных вместо учебного JSON. Основные записи
(операции) по-прежнему хранятся в памяти React и сбрасываются при обновлении
страницы — их перенос и авторизация будут в ЛР 6.

## Supabase как источник справочника
- Проект Supabase: <укажите название проекта, БЕЗ URL и ключей>
- Таблицы: public.categories (справочник), public.transactions (личные операции)
- Справочник заполняется из supabase/seed.sql
- RLS включён на обеих таблицах
- categories: чтение разрешено ролям anon и authenticated, запись — нет
- transactions: клиентских прав и политик нет (до ЛР 6)

Переменные окружения (frontend/.env.local)
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=

Образец без значений — frontend/.env.example.
.env.local в Git не попадает. Secret key и service_role в проекте не используются.

Порядок применения SQL
1. supabase/migrations/001_initial_schema.sql — таблицы, ключи, ограничения,
   RLS, права и политика чтения справочника.
2. supabase/seed.sql — заполнение справочника (идемпотентно, через upsert).

## Запуск
cd frontend

# создать frontend/.env.local по образцу .env.example
npm run dev

и не обращается по адресу undefined.

## Ограничения ЛР-5
- Основные операции остаются в памяти (useState в App), после перезагрузки
  возвращаются демонстрационные записи.
- Постоянным становится только справочник категорий.
- Клиентская запись в справочник запрещена.
- Чтение таблицы transactions из браузера запрещено.


## ЛР-6

Подключена авторизация Supabase Auth и постоянное хранение операций в базе данных.
Каждый пользователь видит только свои операции благодаря RLS-политикам.
Данные сохраняются между перезагрузками страницы.

Новые возможности ЛР-6
- Регистрация и вход через email и пароль (Supabase Auth).
- Кнопка «Выйти» в шапке приложения.
- Операции хранятся в таблице `transactions` в Supabase.
- Каждый пользователь видит и меняет только свои операции (RLS по owner_id).
- После обновления страницы данные сохраняются.
- Справочник категорий по-прежнему публичный, но теперь из Supabase.

Переменные окружения
- `VITE_SUPABASE_URL` — URL проекта Supabase.
- `VITE_SUPABASE_PUBLISHABLE_KEY` — публичный ключ.

Оба значения хранятся в `frontend/.env.local` (не в Git). Образец — в `frontend/.env.example`.

## Ограничения
- Основные операции хранятся в Supabase и доступны после входа.
- Справочник категорий публичный — читается всеми, меняется только в базе.
- Персональные данные защищены RLS: пользователь видит только свои операции.
